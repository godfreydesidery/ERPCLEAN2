# Products Build Brief — mirror Parties exactly, zero guesswork

> Generated from a multi-agent extraction of the shipped Parties/IAM precedents, verified against
> live code (file paths + line-accurate quotes). Single source for building `com.erp.modules.products`.
> Where ADR-0007 prescribes a deliberate divergence from Parties (`companyUid` in bodies, generic
> `code_sequence`, `MoneyDto` promotion), it is called out explicitly.
>
> **Carried-in owner decisions:** quantity scale `NUMERIC(19,6)`; NO tax columns in V3 (reserve
> OQ-PROD-05 for Sales); promote `MoneyDto` to `platform.common.money`; create requests take
> `companyUid` (String).

## 1. Build order (strict dependency sequence)

1. **MoneyDto promotion** — move `MoneyDto` to `com.erp.platform.common.money` (D-12). Update package + imports in parties.
2. **V3 migration** — `backend/src/main/resources/db/migration/V3__products.sql` (8 tables + indexes + permission seed). Never edit V1/V2 (D-14).
3. **Enums** — `products.domain.enums.ProductType { GOODS, SERVICE }`. Reuse `com.erp.platform.common.domain.MasterStatus`.
4. **Entities** — `Product`, `PriceList`, `CodeSequence`, then children `ProductBulkPack`, `ProductBarcode`, `ProductPrice`, `ProductComponent`, `ProductBranch`.
5. **Repositories** — one per entity; each master repo gets `findByUid` + `findCompanyIdByUid` projection. `CodeSequenceRepository` gets the `FOR UPDATE` lock query.
6. **ScopeGuard wiring** — add `ProductRepository` + `PriceListRepository` constructor deps and the two `companyIdOf` cases (D-10). **Not optional — target-uid gates fail closed without it.**
7. **code_sequence / ProductCodeGenerator** — generic counter + generator component.
8. **Guards** — `ProductBranchGuard` + composition same-company check (`ProductCompositionGuard` or a second method).
9. **Services** — `ProductServiceImpl`, `PriceListServiceImpl` (`@Service @Transactional`).
10. **DTOs** — response + create/update requests. **Create requests carry `companyUid` (String), not `companyId`.**
11. **Controllers** — `ProductController`, `PriceListController` in `com.erp.api`, gated by `@perm.has(...)` / `@perm.scoped(...)`.
12. **Tests** — IT extends `PostgresIntegrationTest`; HTTP `*HttpIT`; guard `*GuardIT`; code-gen `*CodeGeneratorIT`.

## 2. The 8 tables — V3__products.sql

**Naming (verified from V1/V2):** master tables plural (`products`, `price_lists`); junction singular (`product_branch`); counter `code_sequence`. Constraint roots **singular** (`uq_product_uid`, `fk_product_company`). Index names: plural master (`ix_products_company`), singular junction (`ix_product_branch_product`). PK `BIGINT GENERATED BY DEFAULT AS IDENTITY`. `uid VARCHAR(26)`. Audit cols: `created_at TIMESTAMPTZ NOT NULL DEFAULT now(), created_by BIGINT, updated_at TIMESTAMPTZ, updated_by BIGINT`. `status VARCHAR(32) NOT NULL DEFAULT 'ACTIVE'`. `version BIGINT NOT NULL DEFAULT 0`.

Table order (D-14): `products` → `code_sequence` → `price_lists` → `product_bulk_packs` → `product_barcodes` → `product_prices` → `product_components` → `product_branch` → indexes → permission seed + grant.

### 2.1 `products`
Cols: id, uid, company_id BIGINT NOT NULL, code VARCHAR(20) NOT NULL, name VARCHAR(200) NOT NULL, description VARCHAR(500), type VARCHAR(20) NOT NULL, sellable BOOLEAN NOT NULL DEFAULT true, stockable BOOLEAN NOT NULL DEFAULT true, base_unit VARCHAR(40) NOT NULL, cost_amount NUMERIC(19,4), cost_currency VARCHAR(3), status, version, audit.
- `uq_product_uid UNIQUE (uid)`; `uq_product_company_code UNIQUE (company_id, code)`; `fk_product_company → companies (id)`
- `chk_product_type CHECK (type IN ('GOODS','SERVICE'))`
- `chk_product_service_stockable CHECK (NOT (type = 'SERVICE' AND stockable = true))` (BR-PROD-01)
- `chk_product_cost_pair CHECK ((cost_amount IS NULL AND cost_currency IS NULL) OR (cost_amount IS NOT NULL AND cost_currency IS NOT NULL))`
- Indexes: `ix_products_company (company_id)`; `ix_products_company_name (company_id, lower(name))`.

### 2.2 `code_sequence` (generic — NOT party_code_sequence)
Cols: id, company_id BIGINT NOT NULL, entity_kind VARCHAR(30) NOT NULL, next_value BIGINT NOT NULL DEFAULT 1, version BIGINT NOT NULL DEFAULT 0.
- `uq_code_sequence UNIQUE (company_id, entity_kind)`; `fk_code_sequence_company → companies (id)`
- **No entity_kind CHECK** — open-ended (this is why `party_code_sequence` with its `party_kind` CHECK can't be reused).

### 2.3 `price_lists` (code user-supplied, not auto-numbered)
Cols: id, uid, company_id, code VARCHAR(20) NOT NULL, name VARCHAR(120) NOT NULL, status, version, audit.
- `uq_price_list_uid UNIQUE (uid)`; `uq_price_list_company_code UNIQUE (company_id, code)`; `fk_price_list_company → companies (id)`; `ix_price_lists_company (company_id)`.

### 2.4 `product_bulk_packs`
Cols: id, uid, product_id BIGINT NOT NULL, name VARCHAR(40) NOT NULL, factor_to_base NUMERIC(19,6) NOT NULL, full audit.
- `uq_product_bulk_pack_uid UNIQUE (uid)`; `uq_product_bulk_pack_name UNIQUE (product_id, name)`; `fk_product_bulk_pack_product → products (id)`; `chk_product_bulk_pack_factor CHECK (factor_to_base > 0)`; `ix_product_bulk_packs_product (product_id)`.

### 2.5 `product_barcodes` (company_id DENORMALISED)
Cols: id, uid, product_id BIGINT NOT NULL, company_id BIGINT NOT NULL, barcode VARCHAR(64) NOT NULL, is_primary BOOLEAN NOT NULL DEFAULT false, created_at, created_by (add/remove — no updated_*).
- `uq_product_barcode_uid UNIQUE (uid)`; `uq_product_barcode_company_value UNIQUE (company_id, barcode)` (BR-PROD-07 + POS lookup); `fk_product_barcode_product → products (id)`; `fk_product_barcode_company → companies (id)`
- **Partial unique (mandatory WHERE):** `CREATE UNIQUE INDEX uq_product_barcode_primary ON product_barcodes (product_id) WHERE is_primary;`
- `ix_product_barcodes_product (product_id)`.

### 2.6 `product_prices` (company_id DENORMALISED; bare amount/currency)
Cols: id, product_id BIGINT NOT NULL, price_list_id BIGINT NOT NULL, company_id BIGINT NOT NULL, amount NUMERIC(19,4) NOT NULL, currency VARCHAR(3) NOT NULL, full audit.
- `uq_product_price UNIQUE (product_id, price_list_id)`; `fk_product_price_product → products (id)`; `fk_product_price_pricelist → price_lists (id)`; `fk_product_price_company → companies (id)`
- No null-together CHECK (both NOT NULL). Entity uses bare `@Embedded` Money (no `@AttributeOverride` — columns are Money's defaults `amount`/`currency`).
- Indexes: `ix_product_prices_product`, `ix_product_prices_list`, `ix_product_prices_company`.

### 2.7 `product_components` (self-referential)
Cols: id, composed_product_id BIGINT NOT NULL, component_product_id BIGINT NOT NULL, quantity NUMERIC(19,6) NOT NULL, created_at, created_by.
- `uq_product_component UNIQUE (composed_product_id, component_product_id)`; `fk_product_component_composed → products (id)`; `fk_product_component_component → products (id)`
- `chk_product_component_not_self CHECK (composed_product_id <> component_product_id)` (BR-PROD-05); `chk_product_component_qty CHECK (quantity > 0)`
- Indexes: `ix_product_components_composed`, `ix_product_components_component`.

### 2.8 `product_branch` (singular junction — no uid/status/version)
Cols: id, product_id BIGINT NOT NULL, branch_id BIGINT NOT NULL, assigned_at TIMESTAMPTZ NOT NULL DEFAULT now(), assigned_by BIGINT NOT NULL.
- `uq_product_branch_pair UNIQUE (product_id, branch_id)`; `fk_product_branch_product → products (id)`; `fk_product_branch_br → branches (id)`; `fk_product_branch_by → app_users (id)`
- Indexes: `ix_product_branch_product`, `ix_product_branch_branch`.

### 2.9 Permission seed + ORG_ADMIN grant (idempotent)
```sql
INSERT INTO permissions (code, module, description) VALUES
    ('PRODUCT.VIEW',          'products', 'View and select products'),
    ('PRODUCT.MANAGE',        'products', 'Create, update, archive products; manage units, barcodes, prices and recipes'),
    ('PRICELIST.VIEW',        'products', 'View price lists'),
    ('PRICELIST.MANAGE',      'products', 'Create, update, archive price lists'),
    ('PRODUCT.BRANCH.ASSIGN', 'products', 'Associate/dissociate a product with branches of its company')
ON CONFLICT (code) DO NOTHING;

INSERT INTO role_permission (role_id, permission_id)
SELECT r.id, p.id FROM roles r CROSS JOIN permissions p
WHERE r.code = 'ORG_ADMIN' AND p.module = 'products'
ON CONFLICT DO NOTHING;
```

## 3. SECURITY (mandatory)

### 3.1 `assertCanActIn` on EVERY read path (the patched Parties fix — replicate all three)
- **list(companyId, q, pageable)** → `scopeGuard.assertCanActIn(RequestContext.get(), companyId)` BEFORE querying (finding 1).
- **getByUid(uid)** → load entity, THEN `scopeGuard.assertCanActIn(RequestContext.get(), entity.getCompanyId())` (finding 2).
- **listBranches / listBarcodes / listBulkPacks / listPrices / listComponents** → scope-check parent product's company before listing children (finding 3).
- **barcode-lookup (POS scan)** → resolve company from `RequestContext` (or guard supplied companyId); query `WHERE company_id = :activeCompany AND barcode = :scanned`. A lookup not constrained by active company is a cross-tenant leak — treat like finding 1.

### 3.2 Same-company guards (cross-row, service-level; ScopeGuard short-circuits root)
- `ProductBranchGuard.resolveAndAssertSameCompany(productCompanyId, branchUid)` — mirror `PartyBranchGuard`; throw `ForbiddenException("... (BR-PROD-09).")`; return branch id.
- `ProductCompositionGuard` — assert `component.companyId == composed.companyId`; throw `"... (BR-PROD-06)."`; reject adding ARCHIVED product as component (BR-PROD-05).
- Order in every mutating op: `assertCanActIn` (authorization) THEN same-company guard (data invariant).

### 3.3 Denormalised company_id invariant
- Map `@Column(name="company_id", nullable=false, updatable=false)` on barcode/price entities.
- Service ALWAYS sets it from `product.getCompanyId()`, never from request/active company.
- **Mandatory regression IT:** after barcode/price create, assert child `company_id == product.company_id`.

## 4. Gates, ScopeGuard, audit, companyUid

### 4.1 Gate API is `@perm.has(...)` / `@perm.scoped(...)` — NOT `hasAuthority` (ADR had this wrong)
`PermissionChecks` bean `@Component("perm")` exposes `has(code)` and `scoped(uid, targetType, code)`.
- `GET /api/v1/products` (list) → `@perm.has('PRODUCT.VIEW')`
- `GET /api/v1/products/uid/{uid}` → `@perm.has('PRODUCT.VIEW')`
- `POST /api/v1/products` → `@perm.scoped(#request.companyUid, 'company', 'PRODUCT.MANAGE')`
- `PUT /api/v1/products/uid/{uid}` (+ archive/restore) → `@perm.scoped(#uid,'product','PRODUCT.MANAGE')`
- `POST/DELETE .../uid/{uid}/branches` → `@perm.scoped(#uid,'product','PRODUCT.BRANCH.ASSIGN')`
- barcodes/bulk-packs/prices/components under product uid → `@perm.scoped(#uid,'product','PRODUCT.MANAGE')`
- `POST /api/v1/price-lists` → `@perm.scoped(#request.companyUid,'company','PRICELIST.MANAGE')`; `PUT .../uid/{uid}` → `@perm.scoped(#uid,'pricelist','PRICELIST.MANAGE')`; list/get → `@perm.has('PRICELIST.VIEW')`

### 4.2 ScopeGuard additions (D-10)
Add `ProductRepository products`, `PriceListRepository priceLists` ctor deps + cases:
```java
case "product"   -> products.findCompanyIdByUid(uid);
case "pricelist" -> priceLists.findCompanyIdByUid(uid);
```
`company` target type already exists, so the create-body gate works as-is.

### 4.3 Audit — `AuditService.record`, target_type = PLURAL table name
Add `PRODUCT_*` / `PRICELIST_*` to `AuditActions`. target_types: `"products"` (create/update/archive/restore/branch add+remove), `"product_barcodes"`, `"product_prices"`, `"product_components"`, `"price_lists"`. Fact-only detail (status transitions carry previous/new status). Same TX.

### 4.4 companyUid in create body
`CreateProductRequest` / `CreatePriceListRequest` carry `@NotBlank String companyUid`. Service resolves uid→id (`companies.findByUid`), then `assertCanActIn`.

## 5. Test checklist (gates this module)

IT extends `com.erp.support.PostgresIntegrationTest` (singleton Testcontainers, Ryuk disabled — never per-class `@Container`/`@Testcontainers` on Windows). `testData.clearAll()` in `@BeforeEach`; set `RequestContext.Principal`; `RequestContext.clear()` in `@AfterEach`.

**Cross-tenant reads blocked:** list own-company only; HTTP `?companyId={B}` with A-token → 403; getByUid cross-company → 403; child lists cross-company → 403; **barcode-lookup cross-company → no resolution/403**.

**DB CHECK/unique fires:** service+stockable; cost pair null-together; bulk-pack factor>0 + dup name; component not-self + qty>0; barcode unique per company; barcode primary partial-unique (one true, many false ok); code unique per company.

**Guards cross-company:** assignBranch BR-PROD-09 ForbiddenException; addComponent BR-PROD-06; addComponent ARCHIVED rejected (BR-PROD-05).

**Numbering:** different companies each get `PROD-0001`; same company → `PROD-0001`,`PROD-0002`; `code_sequence` keyed by `(company_id,'PRODUCT')`.

**Denormalisation:** barcode/price company_id == product company_id.

**Audit:** create writes log, action `PRODUCT.CREATE`, targetType `"products"`, actor/targetUid set.

**HTTP envelope + ArchUnit:** create returns 201, `$.data.code=="PROD-0001"`, `$.data.companyId` is STRING; `ModuleBoundaryTest` passes (no new allowlist entry).

## Key gotchas (load-bearing)
- **`@perm.*` not `hasAuthority`.**
- **`product_prices` bare `@Embedded Money`** (cols `amount`/`currency`); **cost on `products` uses `@AttributeOverride`** → `cost_amount`/`cost_currency`.
- **`code_sequence` has NO entity_kind CHECK** (openness is the point).
- **Junction `product_branch`: no uid/version/status**; uid-addressed children DO carry uid.
- **`MoneyDto.toMoney` returns null if amount OR currency null** — never `new Money(null, ...)` (ctor throws).
- **V1/V2 frozen** — additive V3 only.
