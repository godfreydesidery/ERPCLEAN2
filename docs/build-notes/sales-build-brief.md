**Gotchas to honour:**
- The `products` ALTER MUST be first so the seed and tables see it. Safe because `DEFAULT 'STANDARD'`.
- `chk_sales_invoice_number_when_finalised` is the critical immutability gate â€” finalise MUST set `status` and `invoice_number` in **one TX** or the CHECK fires.

## 4. SECURITY (mandatory â€” release blocker if missed)

**(a) `assertCanActIn` on EVERY read path.** Copy `ProductServiceImpl` exactly:
- `list(companyId, â€¦)` â€” `scopeGuard.assertCanActIn(RequestContext.get(), companyId)` **before** the query (ProductServiceImpl line 151).

- `listLines(invoiceUid)`, `listPayments(invoiceUid)` â€” load parent, `assertCanActIn`, then list children (line 235-238 pattern).
- All mutations begin the same way.

**(b) Create-path company resolution.** `CreateSalesInvoiceRequest` carries `companyUid` (String). **(c) Cross-tenant same-company resolution (the F15 pattern â€” verified in `ProductServiceImpl.resolveUnit` line 482-485 and `setPrice` line 345).** Every cross-module ref is resolved **scoped to the invoice's company**, throwing `NotFoundException` if it belongs to another company:

## 5. The tax-EXCLUSIVE totals algorithm (copy-ready) â€” `InvoiceTotalsCalculator`

Service-computed and **stored** (NOT DB-generated; ADR-0008 D-4). The unit price entered is **net** (before VAT); VAT is added on top. Rounding: **HALF_UP** to the currency's minor units (TZS = 0 dp, default per OQ-CUR-03; storage is `NUMERIC(19,4)`), at each boundary, never between intermediate steps. The web must mirror this exactly (NFR-SALES-02).

**Algorithm (ADR-0008 D-4 Â§1-6):**
1. Per line: `lineNet = round(unitPrice Ã— quantity) âˆ’ lineDiscount` (line discount resolved from amount OR percent; discount before VAT).
2. Apportion the document discount pro-rata across lines by each line's `lineNet`; recompute each line's discounted taxable net.
3. Per line: `vat = round(discountedNet Ã— vatRate)` (0 for ZERO_RATED/EXEMPT); `lineGross = discountedNet + vat`.
4. Header: `net_total = Î£ discountedNet`; `vat_total = Î£ vat`; `gross_total = net_total + vat_total`.
5. `tax_summary` = group lines by `(vat_status, vat_rate)`, summing net + vat per band â†’ JSONB array `[{"status":"STANDARD","rate":"0.1800","net":"â€¦","vat":"â€¦"}]`.
6. Recompute + re-store on every DRAFT mutation; freeze at finalise; VOID does not recompute.

**Worked numeric example (TZS, STANDARD = 18%, no document discount):**
- Line 1: qty 1 Ã— net 1000, no discount â†’ `net = 1000`, `vat = round(1000 Ã— 0.18) = 180`, `gross = 1180`.
- Line 2: qty 2 Ã— net 500, line discount 100 â†’ `net = (2Ã—500) âˆ’ 100 = 900`, `vat = round(900 Ã— 0.18) = 162`, `gross = 1062`.
- Header: `net_total = 1900`, `vat_total = 342`, `gross_total = 2242`.
- `tax_summary = [{"status":"STANDARD","rate":"0.1800","net":"1900.0000","vat":"342.0000"}]`.

A FINALISE then allocates `INV-0001` and requires tenders summing to `2242` (e.g. 2000 cash + 242 mobile_money; or 2500 cash â†’ `change_amount = 258`).
