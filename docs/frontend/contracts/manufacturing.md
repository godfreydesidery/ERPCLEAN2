# API Contract — manufacturing module (Phase-B frontend)

**Nav group:** Manufacturing  
**Permission codes (use VERBATIM — do not invent):** MANUFACTURING.VIEW, WORKORDER.MANAGE, WORKORDER.RELEASE, WORKORDER.CLOSE

## Module notes
PAGINATION: Only GET /api/v1/work-orders (list) is paginated â€” Spring Pageable (page/size/sort) + PageMeta in the ApiResponse envelope; it requires query param companyId:Long and accepts optional status:WorkOrderStatus filter. All other GETs (getByUid, cost-report, wip-reconciliation) return single objects, not paged.

RESPONSE ENVELOPE: Every endpoint is auto-wrapped in ApiResponse<T> by ApiResponseAdvice. List endpoints add PageMeta. Long ids are serialised as JSON strings; treat Long/BigDecimal/Integer as string on the wire.

LIFECYCLE STATE MACHINE (WorkOrderStatus): PLANNED -> RELEASED -> IN_PROGRESS -> COMPLETED -> CLOSED (terminal); CANCELLED (terminal). Actions + preconditions:
- create: produces PLANNED.
- update (PUT): PLANNED only (edit qty/BOM/branch/dates/notes).
- release: PLANNED -> RELEASED. Explodes BOM, materialises component plan lines, pins bomId/bomUid. No stock/GL effect. Rejected if BOM unresolvable / no leaves.
- issue-components: RELEASED or IN_PROGRESS. First issue transitions RELEASED -> IN_PROGRESS. Posts PRODUCTION_ISSUE movements.
- apply-cost: order with WIP accumulating; idempotent per operation (applied flag).
- complete: IN_PROGRESS -> COMPLETED. Computes finished unit cost, FG receipt + WIP relief.
- close: COMPLETED -> CLOSED. Clears residual WIP to variance (terminal).
- cancel: from PLANNED/RELEASED/IN_PROGRESS (enum graph also allows from COMPLETED); reverses all posted issues/receipts/labour at ORIGINAL cost. Rejected from CLOSED.

PERMISSION GAP / GOTCHA (controller is authoritative â€” ADR prose is stale): complete() is gated @perm.scoped WORKORDER.CLOSE (NOT WORKORDER.MANAGE as the ADR D-2 text says); close() also WORKORDER.CLOSE. cancel() and issue/apply/add/remove-operation use WORKORDER.MANAGE. release() uses WORKORDER.RELEASE. List + detail + cost-report + wip-recon use MANUFACTURING.VIEW. So WORKORDER.CLOSE governs BOTH complete and close.

SCOPED vs HAS PERMS: list/create/wip-recon use @perm.has (company-wide); all uid-targeted endpoints use @perm.scoped(#uid,'workorder',CODE). The scope target type literal is 'workorder'. Controllers also call scopeGuard.assertCanActIn(RequestContext.get(), companyId) on the two company-param endpoints (list, wip-reconciliation).

PATH NOTE: the issue action endpoint path is /issue-components (the ADR/service text calls the method 'issue' but the wire path is issue-components). cancel takes its reason via ?reason= query param (no body). release accepts an OPTIONAL body (required=false) â€” the {bomUid} may be omitted entirely.

MONEY / CURRENCY: All amounts are base currency only (BR-MFG-07), HALF_UP. No currency code field anywhere in the DTOs. Cost/value fields use scale 4 (NUMERIC 19,4): wipDebitTotal, wipCreditTotal, labourAppliedTotal, overheadAppliedTotal, computedUnitCost, varianceAmount, issuedValue, unitCostAtIssue, labourAmount, overheadAmount, and the recon computed/expected. Quantity fields use scale 6 (NUMERIC 19,6): plannedQty, goodQty, scrapQty, component plannedQty/issuedQty. varianceAmount is SIGNED (positive=under-relieved cost, negative=over-relieved credit).

REPORT ENDPOINT SHAPES: (1) /work-orders/uid/{uid}/cost-report -> WorkOrderCostReportDto: header summary (woNumber, finished product code/name, planned/good/scrap qty), WIP accumulators (wipDebitTotal, wipCreditTotal, labourAppliedTotal, overheadAppliedTotal), computedUnitCost, varianceAmount, incompleteCost flag, plus full components[] and operations[] arrays. (2) /manufacturing/wip-reconciliation -> WipReconciliationDto: { label, computed, expected, ties }. ties is computed.compareTo(expected)==0; render ties=false as a finance defect/warning. Reconciles Î£ open-WO WIP (RELEASED/IN_PROGRESS/COMPLETED only; CLOSED/CANCELLED excluded) vs the WIP_INVENTORY (1320) GL account balance.

CHILD / NESTED RESOURCES: WorkOrderDto embeds two child arrays returned inline on detail/create/update â€” components[] (WorkOrderComponentDto: id, uid, workOrderId, lineNo, componentProductId, componentProductCode, componentProductName, plannedQty, issuedQty, issuedValue, unitCostAtIssue, costSkipped, status:ComponentLineStatus) and operations[] (WorkOrderOperationDto: id, uid, workOrderId, seqNo, description, workCentre, labourAmount, overheadAmount, applied:boolean). Components are auto-generated by the BOM explosion at RELEASE (no create/delete endpoint for component lines). Operations are managed via POST /operations (add) and DELETE /operations/{opUid} (remove) â€” these are the only writable child resource. ComponentLineStatus enum: PLANNED, PARTIAL, ISSUED. incompleteCost/costSkipped surface the null-avg-cost warning state (a component issued with no established moving-average cost).

GL ACCOUNTS REFERENCED (for FE labels/help, not endpoints): WIP_INVENTORY=1320, FINISHED_GOODS->1300 (v1), LABOUR_APPLIED=2350, OVERHEAD_APPLIED=2360, MANUFACTURING_VARIANCE=5180. New stock MovementType values: PRODUCTION_ISSUE, PRODUCTION_RECEIPT, PRODUCTION_ISSUE_REVERSAL, PRODUCTION_RECEIPT_REVERSAL.
