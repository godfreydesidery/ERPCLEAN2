# API Contract — crm module (Phase-B frontend)

**Nav group:** CRM  
**Permission codes (use VERBATIM — do not invent):** CRM.LEAD.VIEW, CRM.LEAD.MANAGE, CRM.LEAD.QUALIFY, CRM.OPPORTUNITY.VIEW, CRM.OPPORTUNITY.MANAGE, CRM.OPPORTUNITY.CONVERT, CRM.PIPELINE.VIEW, CRM.STAGE.MANAGE

## Module notes
SCOPE OF THIS EXTRACTION: Only the 4 controllers requested (LeadController, OpportunityController, PipelineController, PipelineStageController). ADR-0031 also defines an ActivityController + CRM.ACTIVITY.VIEW/CRM.ACTIVITY.MANAGE perms, but that controller was NOT in the requested set and is NOT covered here. So the full module perm catalog includes 2 more codes (CRM.ACTIVITY.VIEW, CRM.ACTIVITY.MANAGE) not listed above.

RESPONSE ENVELOPE (IMPORTANT, inconsistent across endpoints):
- ONLY the two collection list endpoints are wrapped: GET /crm/leads and GET /crm/opportunities return ApiResponse<List<T>> with data + meta(PageMeta). These are the ONLY paginated endpoints (Spring Pageable: ?page=&size=&sort=). PageMeta = {page:int(0-based), size:int, totalElements:int, totalPages:int, hasNext:bool} â€” all plain JSON numbers.
- EVERYTHING ELSE returns the bare DTO/array directly, NOT wrapped in ApiResponse (no data/meta envelope): all getByUid, create, update, all action endpoints, GET /crm/pipeline-stages (bare List, NOT paginated), GET /crm/opportunities/uid/{uid}/lines (bare List), and all 3 pipeline report endpoints.
- Global serialization: Long ids (id, companyId, branchId, ownerUserId, customerId, agentId, sourceLeadId, pipelineStageId, version, createdBy, updatedBy) serialize as JSON STRINGS. BigDecimal money/probability also as strings. counts (openCount, wonCount, lostCount in report DTOs) are 'long' -> also serialize as strings.

PATH SHAPE: all single-resource paths use the /uid/{uid} segment (e.g. GET /api/v1/crm/leads/uid/{uid}), NOT /{uid} directly. Path var names: {uid} on all; opportunity line delete uses {uid} (opportunity) + {lineUid} (line).

PERMISSION GATING (copied verbatim): list/create use @perm.has('CODE'); per-record reads/writes use @perm.scoped(#uid,'<targettype>','CODE') where targettype is 'lead' | 'opportunity' | 'pipelinestage'. Notable: pipeline-stage VIEW reuses CRM.OPPORTUNITY.VIEW (there is no CRM.STAGE.VIEW). Pipeline reports use CRM.PIPELINE.VIEW. Two action bodies are NOT @Valid-annotated on the controller (qualify, win) so bean-validation constraints on QualifyLeadRequest/WinOpportunityRequest are NOT enforced at the controller boundary â€” service does runtime checks instead.

LEAD STATE MACHINE: NEW --contact--> CONTACTED; (NEW|CONTACTED) --qualify--> QUALIFIED (must resolve a customer: link existingCustomerUid OR promote via Parties CustomerService.create with newCustomerDetails; exactly one); QUALIFIED --(opportunity created with sourceLeadUid)--> CONVERTED (terminal, set by OpportunityController create, not a lead endpoint); any non-terminal --disqualify--> DISQUALIFIED (terminal, reason mandatory). update/contact/qualify/disqualify all rejected once CONVERTED or DISQUALIFIED. contact requires current=NEW.

OPPORTUNITY STATE MACHINE: created OPEN at one pipeline stage. OPEN editable (update/addLine/removeLine/advance-stage all require OPEN). --win--> WON (requires OPEN; wonAt set), --lose--> LOST (requires OPEN; lossReason mandatory; terminal). WON/LOST are closed (no further edits except convert). CONVERT GATE: target=QUOTATION allowed when status OPEN or WON (stays in its status); target=SALES_ORDER requires status=WON; LOST can never convert. Convert is IDEMPOTENT â€” second call returns the existing convertedDocumentUid (with convertedDocumentNumber=null). Convert REQUIRES >=1 opportunity line. Convert calls Sales O2C (QuotationService/SalesOrderService create+addLine) and stamps convertedDocumentKind/Uid/At; CRM itself posts no GL, moves no stock, opens no AR.

MONEY/CURRENCY FIELDS: Opportunity.estimatedValueAmount (BigDecimal), Opportunity.currency (3-char), OpportunityLine.estimatedUnitPriceAmount/lineDiscountAmount/lineDiscountPercent + line currency, winProbability/defaultProbability are 0..100 percentages (BigDecimal). Pipeline reports: totalValueAmount/weightedValueAmount + currency. All amounts are estimates only (no VAT/net/gross computed in CRM).

REPORT ENDPOINT SHAPES (all under /crm/pipeline, all GET, all CRM.PIPELINE.VIEW, all require companyId+branchId query params; forecast/kpis also require from+to ISO dates yyyy-MM-dd): pipeline -> PipelineSummaryDto{stages:[{stageUid,stageName,displayOrder,openCount,totalValueAmount,weightedValueAmount,currency}]}; forecast -> ForecastDto{periodStart,periodEnd,weightedValueAmount,openCount,currency}; kpis -> CrmKpiDto{periodStart,periodEnd,wonCount,lostCount,winRatePercent,avgCycleDays}.

CHILD/NESTED RESOURCES: Opportunity lines are a nested resource under /crm/opportunities/uid/{uid}/lines (GET list bare array, POST add 201, DELETE /{lineUid} 204). Lines are also embedded inline in OpportunityDto.lines on every opportunity read (getByUid + list). OpportunityLineDto fields: id, uid, opportunityId, companyId, branchId, lineNo(short), productId, productCode, productName, unitId, unitName, estimatedQty(BigDecimal), estimatedUnitPriceAmount(BigDecimal), lineDiscountAmount(BigDecimal), lineDiscountPercent(BigDecimal), currency, version, createdAt, createdBy.

CROSS-MODULE UID REFS the FE may need to resolve for display: customerUid (Parties customer), agentUid (Parties agent â€” note: stored as agentId, NOT exposed as uid on OpportunityDto, only agentId), sourceLeadUid, pipelineStageUid->pipelineStageId, ownerUserId (IAM app_user), product/unit uids on lines, convertedDocumentUid (a Sales Quotation or SalesOrder uid).

SUGGESTED FE ROUTES (per ADR-0031 D-11): /crm/leads, /crm/leads/:uid, /crm/opportunities, /crm/opportunities/:uid, /crm/pipeline (board+forecast+kpis), /crm/settings/pipeline-stages (admin, gated CRM.STAGE.MANAGE).
