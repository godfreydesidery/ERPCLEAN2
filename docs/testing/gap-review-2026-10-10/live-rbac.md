# Live RBAC test (non-root staff): OrbixERP develop build on :8091

**Method.** I created one RB- user for each of 11 seeded roles. I added a branch-2 salesperson (`rb-arusha-sales`) and a cashier whose role is granted at branch scope (`rb-cashier-br`). Every user was onboarded exactly the way the web user-admin screens do it.

A static analyser (`fe_map.py`) walked the Angular code: nav item → route guard → component and its child pickers → the service methods those components actually call → the backend `@PreAuthorize`. It covered 773 endpoints, 217 routes and 142 nav items. Every GET with no path placeholder on a nav-visible screen was then called live as each role (`probe.py`). Daily write flows were run live (`pos_flow*.py`, `daily*.py`). Each candidate 403 was checked in the component to see whether the UI gates it or swallows it, and only the ones a user can actually see are reported.

**Owner questions, answered:**
- **Can a branch manager see all-branch reports?** Unfiltered: yes, and it includes Arusha (sales report shows SF-COKE350 qty 49 = 9 from Head Office + 40 from Arusha). Filtered to a single other branch: no, 403. The branch-1 salesperson sees the same thing, and a branch-1 BM can open an Arusha invoice by uid (200).
- **Can the accountant post what they need?** Journals, receipts, AP and VAT prep: yes. 3-way bill matching against a PO, sales-invoice reconciliation and FX rates: no.
- **Can a storekeeper receive without a purchasing permission?** Yes.
- **Can a cashier look up stock and price?** Yes: POS resolve/on-hand, and web Item Inquiry returns the price list and stock.
- **Phantom codes:** none. Every code referenced in `@PreAuthorize`, programmatic `perm.has`, ImportHandlers, route guards and nav is seeded. The reverse problem exists, though (LRB-15).

## (3) Top 5
1. **LRB-01**: Procurement can't set selling prices in Product Master (price-lists 403 shown as "No active price lists"). New items reach the till unpriced.
2. **LRB-02**: Van reconciliation is dead for the only non-admin role allowed to do it (FIELD_SALES_AGENT lacks STOCK.LOCATION.VIEW).
3. **LRB-04**: The accountant/FD can't link a supplier bill to PO lines or GRNs. PO-lines and GRN reads omit AP.BILL.ENTER, which the PO list already allows.
4. **LRB-03**: The cashier's Cash Count screen can't list tills (CASH.VIEW) and claims there are none.
5. **LRB-06 / LRB-05**: Branch drill-down is refused while company-wide totals already show the branch, and a fully cash-paid sale to an over-limit credit customer is blocked as a "permission" problem.
